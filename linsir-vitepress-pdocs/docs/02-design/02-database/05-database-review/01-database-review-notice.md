## 六、评审标准

### 6.1 评审通过标准

评审结论分为三种：

| 结论 | 说明 | 后续动作 |
|-----|------|---------|
| **通过** | 设计满足要求，无需修改或仅需微调 | 建立基线，进入开发阶段 |
| **有条件通过** | 设计基本满足要求，存在少量问题需修改 | 修改后重新审核，确认后建立基线 |
| **不通过** | 设计存在重大问题，需要重新设计 | 重新设计后再次组织评审 |

### 6.2 问题分级标准

| 级别 | 说明 | 处理要求 |
|-----|------|---------|
| **严重** | 影响系统功能、性能、安全的设计缺陷 | 必须修改，不修改不能通过 |
| **中等** | 影响代码质量、可维护性的问题 | 建议修改，可在后续迭代优化 |
| **轻微** | 编码风格、注释等细节问题 | 可选修改，不强制要求 |
