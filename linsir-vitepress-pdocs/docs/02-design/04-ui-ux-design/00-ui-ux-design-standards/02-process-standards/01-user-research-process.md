## 3. 核心任务

### 3.1 分析用户画像

**目标**: 从业务需求中提取设计相关的用户特征

**输入**:
- 业务需求文档中的用户画像
- 用户旅程地图
- 痛点与期望分析

**输出**: `01-user-personas-design.md`

**关键活动**:
- 提取用户基本信息（年龄、职位、技术能力）
- 分析用户目标与动机
- 识别用户痛点和期望
- 定义用户使用场景

**检查点**:
- [ ] 是否覆盖所有用户类型
- [ ] 是否包含用户技术能力评估
- [ ] 是否明确用户核心需求

---

### 3.2 研究行为模式

**目标**: 了解用户的工作习惯和操作偏好

**输入**:
- 用户画像
- 业务流程文档
- 竞品分析报告

**输出**: `02-user-behavior-patterns.md`

**关键活动**:
- 分析用户日常工作流程
- 识别高频操作和低频操作
- 研究用户的设备使用习惯
- 记录用户的操作时间分布

**检查点**:
- [ ] 是否识别出关键操作路径
- [ ] 是否分析了操作频率
- [ ] 是否考虑了多设备场景

---

### 3.3 调研交互习惯

**目标**: 了解用户对界面交互的偏好

**输入**:
- 行为模式分析结果
- 竞品交互分析
- 行业最佳实践

**输出**: `03-interaction-habits-research.md`

**关键活动**:
- 调研常用操作方式（点击、拖拽、快捷键）
- 分析用户对反馈的期望
- 研究错误处理偏好
- 了解导航习惯

**检查点**:
- [ ] 是否明确了主要交互方式
- [ ] 是否定义了反馈机制
- [ ] 是否考虑了无障碍需求

---

### 3.4 收集视觉偏好

**目标**: 了解用户对界面风格的偏好

**输入**:
- 品牌指南
- 竞品视觉分析
- 用户调研数据

**输出**: `04-visual-preference-research.md`

**关键活动**:
- 调研色彩偏好
- 分析布局偏好
- 了解字体和图标偏好
- 收集视觉参考案例

**检查点**:
- [ ] 是否确定了主色调方向
- [ ] 是否明确了布局风格
- [ ] 是否收集了足够的参考案例

---

### 3.5 细化设计场景

**目标**: 将业务场景转化为设计场景

**输入**:
- 用户旅程地图
- 业务流程文档
- 用户画像

**输出**: `05-design-scenarios.md`

**关键活动**:
- 定义核心使用场景
- 描述用户操作步骤
- 识别场景中的关键决策点
- 定义场景成功标准

**检查点**:
- [ ] 是否覆盖了所有核心功能
- [ ] 场景描述是否具体可执行
- [ ] 是否考虑了异常情况

---

### 3.6 识别设计机会

**目标**: 从研究中发现设计改进机会

**输入**:
- 所有前期研究成果
- 痛点分析
- 竞品对比

**输出**: `06-design-opportunities.md`

**关键活动**:
- 汇总用户痛点
- 对比竞品优劣
- 识别差异化机会
- 定义设计目标

**检查点**:
- [ ] 是否列出了具体的设计机会
- [ ] 是否评估了机会优先级
- [ ] 是否与业务目标对齐

---

### 3.7 编写研究报告

**目标**: 整理研究成果，形成完整报告

**输入**: 所有前期研究文档

**输出**: `07-user-research-review-record.md`

**关键活动**:
- 汇总所有研究发现
- 提炼设计原则
- 制定设计策略
- 准备评审材料

**检查点**:
- [ ] 报告结构是否完整
- [ ] 发现是否有数据支撑
- [ ] 建议是否具体可行

## 4. 评审标准

### 4.1 评审内容

| 检查项 | 标准 | 权重 |
|--------|------|------|
| 用户画像完整性 | 覆盖所有用户类型 | 20% |
| 行为分析深度 | 识别关键操作路径 | 20% |
| 交互偏好明确 | 定义清晰的交互原则 | 20% |
| 视觉方向清晰 | 有明确的视觉偏好 | 20% |
| 设计机会具体 | 机会点可落地执行 | 20% |

### 4.2 评审参与者

- UI/UX设计师（主导）
- 产品经理
- 前端负责人
- 用户代表（可选）

## 6. 常见问题

### Q1: 用户研究需要多少样本？
**A**: 建议至少覆盖3-5个典型用户代表，确保覆盖主要用户类型。

### Q2: 如何确保研究结果的准确性？
**A**: 采用多源验证，结合用户访谈、问卷调研、数据分析等多种方法。

### Q3: 研究结果与业务需求冲突怎么办？
**A**: 优先满足业务目标，同时通过设计手段优化用户体验，必要时组织讨论会。

## 7. 最佳实践

1. **尽早开始**: 在项目启动初期就开始用户研究
2. **持续迭代**: 研究不是一次性活动，需要持续更新
3. **数据支撑**: 所有结论都需要有数据或案例支撑
4. **可视化呈现**: 使用图表、画像等可视化方式呈现研究结果
5. **跨团队协作**: 邀请开发、产品团队参与研究过程
