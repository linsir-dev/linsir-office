# 需求调研报告流程规范

## 概述

本文档定义了需求调研与分析阶段最终交付物——需求调研报告的标准流程，用于汇总所有调研成果。

---

## 报告创建流程

### 第一步：执行摘要

**目标：** 提供调研发现的高层次概述

**执行步骤：**
1. 总结调研范围和时间线
2. 列出访谈的干系人
3. 突出发现的主要痛点
4. 说明识别的关键需求
5. 呈现推荐的解决方案

**关键要素：**
- 项目概述
- 调研时间线
- 关键发现（3-5个要点）
- 推荐方案
- 预期成果

---

### 第二步：调研背景与目标

**目标：** 记录为什么进行调研以及目标是什么

**执行步骤：**
1. 描述当前业务背景
2. 列出现有问题和挑战
3. 定义调研目标
4. 说明成功标准

**内容结构：**
```markdown
## 调研背景
- 当前状态描述
- 业务挑战
- 痛点总结

## 调研目标
- 主要目标
- 次要目标
- 成功标准
```

---

### 第三步：调研方法

**目标：** 记录用于收集需求的方法

**执行步骤：**
1. 列出所有使用的调研方法
2. 描述参与者选择标准
3. 记录数据收集过程
4. 解释分析方法

**需要记录的方法：**
- 用户访谈（谁、多少、时长）
- 现状分析（审查的系统）
- 竞品分析（评估的产品）
- 文档分析（审查的工件）
- 观察（如适用）

---

### 第四步：用户访谈总结

**目标：** 综合所有用户访谈的发现

**执行步骤：**
1. 按角色总结访谈参与者
2. 提取访谈中的共同主题
3. 记录角色特定需求
4. 列出冲突需求（如有）
5. 按频率/影响排序发现

**结构：**
- 参与者概述表
- 共同主题部分
- 角色特定发现
- 关键引用（匿名）
- 提取的需求

---

### 第五步：现状分析

**目标：** 记录系统和流程的当前状态

**执行步骤：**
1. 列出所有现有系统
2. 记录系统能力和限制
3. 绘制当前业务流程
4. 识别痛点和瓶颈
5. 评估集成需求

**内容：**
- 系统清单表
- 流程图
- 痛点分析
- 差距评估
- 技术债务识别

---

### 第六步：竞品分析总结

**目标：** 总结竞争格局和最佳实践

**执行步骤：**
1. 列出分析的竞品
2. 比较功能集
3. 识别竞争优势
4. 记录经验教训
5. 推荐差异化策略

**结构：**
- 竞品概述
- 功能对比矩阵
- SWOT分析
- 识别的最佳实践
- 建议

---

### 第七步：干系人分析总结

**目标：** 记录关键干系人及其利益

**执行步骤：**
1. 列出所有识别的干系人
2. 记录影响力和利益水平
3. 总结每个干系人的关键关注点
4. 记录沟通策略
5. 识别潜在冲突

**内容：**
- 干系人登记册摘要
- 影响力-利益矩阵
- 关键关注点表
- 管理策略

---

### 第八步：需求总结

**目标：** 整合所有功能性和非功能性需求

**执行步骤：**
1. 按模块总结功能需求
2. 按角色列出用户故事
3. 记录非功能需求
4. 识别约束和假设
5. 将需求映射到业务目标

**结构：**
- 功能需求摘要
- 用户故事统计
- 非功能需求
- 约束和假设
- 追溯矩阵（可选）

---

### 第九步：用户画像总结

**目标：** 呈现识别的关键用户画像

**执行步骤：**
1. 列出所有创建的画像
2. 总结每个画像的档案
3. 记录每个画像的关键痛点
4. 列出画像特定需求
5. 按影响排序画像

**内容：**
- 画像概述表
- 详细画像档案（2-3个关键画像）
- 旅程图亮点
- 痛点总结

---

### 第十步：业务流程总结

**目标：** 记录关键业务流程

**执行步骤：**
1. 列出核心业务流程
2. 总结流程流
3. 记录业务规则
4. 识别异常场景
5. 定义流程指标

**结构：**
- 流程清单
- 流程流摘要
- 业务规则表
- 异常处理
- KPI和指标

---

### 第十一步：优先级评估总结

**目标：** 呈现优先级排序结果

**执行步骤：**
1. 总结MoSCoW分类结果
2. 呈现价值-成本分析
3. 列出P0/P1/P2需求
4. 记录迭代计划
5. 识别风险和依赖

**内容：**
- MoSCoW分布
- 优先级矩阵摘要
- 迭代计划概述
- 风险评估
- 建议理由

---

### 第十二步：结论与建议

**目标：** 基于调研提供可执行的建议

**执行步骤：**
1. 总结关键结论（3-5点）
2. 提供分阶段实施建议
3. 识别风险和缓解策略
4. 定义下一步行动
5. 列出开放问题（如有）

**结构：**
- 关键结论
- 实施建议
- 风险缓解
- 下一步行动
- 开放问题

## 质量检查清单

- [ ] 执行摘要简洁全面
- [ ] 调研方法清晰记录
- [ ] 包含所有主要发现
- [ ] 需求可追溯到来源
- [ ] 优先级有理由支持
- [ ] 建议可执行
- [ ] 风险已识别
- [ ] 下一步行动已定义
- [ ] 列出所有参考文档
- [ ] 报告已获干系人审核

---

## 最佳实践

1. **保持简洁** - 关注关键发现，而非原始数据
2. **使用可视化** - 表格、图表和流程图有助于理解
3. **保持客观** - 呈现事实，而非观点
4. **链接到来源** - 参考详细文档以深入了解
5. **排序发现** - 突出最重要的发现
6. **使其可执行** - 提供清晰的建议
7. **获取反馈** - 定稿前让干系人审核

---

## 常见陷阱

- **细节过多** - 报告应总结，而非替代详细文档
- **缺少背景** - 确保读者理解背景
- **无根据的声明** - 用证据支持发现
- **忽略冲突** - 明确记录冲突需求
- **没有清晰建议** - 始终提供可执行的下一步
- **忘记风险** - 尽早识别潜在问题
