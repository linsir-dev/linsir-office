# 用户画像流程规范

## 概述

本文档定义了需求调研与分析阶段中用户画像创建的标准流程，用于系统化地理解用户需求、行为和痛点。

---

## 分析流程

### 第一步：定义用户角色

**目标：** 识别并定义所有将使用系统的用户角色

**执行步骤：**
1. 审查业务需求和干系人分析
2. 基于职责识别不同的用户类型
3. 定义角色属性（权限、范围、频率）
4. 为每个角色创建典型用户档案
5. 记录角色关系和层级

**输出文档：** `01-user-roles.md`

**文档编号：** SYS-RA-UP-001

---

### 第二步：分析使用场景

**目标：** 记录每个用户角色的典型场景

**执行步骤：**
1. 识别每个角色的关键任务
2. 定义场景触发条件和频率
3. 记录逐步工作流程
4. 识别每个场景中的痛点
5. 捕获用户期望

**输出文档：** `02-usage-scenarios.md`

**文档编号：** SYS-RA-UP-002

---

### 第三步：绘制用户旅程图

**目标：** 可视化用户跨触点的体验流程

**执行步骤：**
1. 定义旅程阶段（发现、登录、使用、退出）
2. 映射每个阶段的用户行为
3. 识别触点（页面、系统）
4. 绘制情绪曲线
5. 突出痛点和机会点

**输出文档：** `03-user-journey-map.md`

**文档编号：** SYS-RA-UP-003

---

### 第四步：识别痛点和期望

**目标：** 系统化地捕获用户挫折和愿望

**执行步骤：**
1. 从访谈和场景中收集痛点
2. 按影响程度和频率分类
3. 将痛点映射到用户期望
4. 基于业务价值确定优先级
5. 链接到功能需求

**输出文档：** `04-pain-points-expectations.md`

**文档编号：** SYS-RA-UP-004

---

### 第五步：输出用户画像文档

**目标：** 创建全面的可视化用户画像

**执行步骤：**
1. 将所有研究综合成画像卡片
2. 包括人口统计、目标、行为
3. 添加语录和个性特征
4. 记录痛点和期望
5. 包括设备和使用偏好

**输出文档：** `05-user-persona-document.md`

**文档编号：** SYS-RA-UP-005

## 质量检查清单

- [ ] 所有干系人都被表示为用户角色
- [ ] 场景覆盖主要用户任务
- [ ] 旅程图包含情绪曲线
- [ ] 痛点按影响程度确定优先级
- [ ] 画像感觉像真实的人
- [ ] 画像基于实际研究
- [ ] 每个画像都有独特的特征

---

## 最佳实践

1. **基于研究** - 使用访谈数据，而非假设
2. **保持真实** - 画像应该感觉像真实的人
3. **关注行为** - 不只是人口统计
4. **限制数量** - 通常3-5个画像就足够了
5. **可视化** - 使用图片和格式
6. **广泛分享** - 确保团队参考画像
7. **保持更新** - 随着了解更多而刷新

---

## 常见陷阱

- **画像太多** - 关注主要用户
- **太通用** - 包括具体细节
- **基于假设** - 始终用研究验证
- **创建后被忽视** - 在设计决策中参考
- **从不更新** - 定期刷新
