## 一、流程概述

### 1.1 流程基本信息

| 属性 | 描述 |
|-----|------|
| 流程名称 | 用户入职流程 |
| 流程编号 | BP-USER-001 |
| 流程类型 | 核心业务流程 |
| 触发条件 | HR系统发送新员工入职通知 |
| 主要参与者 | HR专员、系统管理员、部门管理员、新员工 |
| 流程目标 | 为新员工创建系统账号并分配权限 |

### 1.2 流程目标

- 确保新员工入职第一天即可使用系统
- 保证用户数据准确性和完整性
- 分配合适的权限和角色
- 记录完整的入职操作日志

## 三、流程步骤详细说明

### 步骤1：发送入职通知

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S1 |
| 步骤名称 | 发送入职通知 |
| 执行角色 | HR专员 |
| 输入 | 新员工入职申请表 |
| 输出 | 入职通知（含员工基本信息） |
| 触发条件 | 新员工入职审批通过 |

**操作细节：**
1. HR专员在HR系统中确认新员工入职信息
2. 系统自动发送入职通知到System平台
3. 通知包含：姓名、工号、部门、岗位、入职日期

---

### 步骤2：创建用户账号

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S2 |
| 步骤名称 | 创建用户账号 |
| 执行角色 | 系统管理员 |
| 输入 | 入职通知信息 |
| 输出 | 新建用户账号 |
| 处理时间 | ≤ 5分钟 |

**操作细节：**
1. 系统管理员收到入职通知
2. 登录System平台，进入用户管理
3. 点击"创建用户"
4. 系统自动填充：姓名、工号、部门、岗位
5. 设置初始密码（随机生成）
6. 保存用户信息

**业务规则：**
- 用户名默认使用工号
- 邮箱格式：工号@company.com
- 初始密码有效期为7天

---

### 步骤3：分配基础角色

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S3 |
| 步骤名称 | 分配基础角色 |
| 执行角色 | 系统管理员 |
| 输入 | 用户岗位信息 |
| 输出 | 角色分配结果 |

**操作细节：**
1. 根据岗位自动匹配默认角色
2. 系统管理员确认或调整角色
3. 保存角色分配

**角色映射规则：**
| 岗位类型 | 默认角色 |
|---------|---------|
| 管理层 | 部门管理员 |
| 普通员工 | 普通用户 |
| 技术人员 | 普通用户 + 技术权限 |
| 财务人员 | 普通用户 + 财务权限 |

---

### 步骤4：通知部门管理员

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S4 |
| 步骤名称 | 通知部门管理员 |
| 执行角色 | 系统（自动） |
| 输入 | 用户创建完成 |
| 输出 | 通知邮件/消息 |

**操作细节：**
1. 系统自动识别用户所属部门
2. 查找部门管理员
3. 发送通知：新员工已创建，请分配具体权限

---

### 步骤5：分配部门权限

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S5 |
| 步骤名称 | 分配部门权限 |
| 执行角色 | 部门管理员 |
| 输入 | 新员工信息 |
| 输出 | 部门权限分配结果 |
| 处理时间 | ≤ 10分钟 |

**操作细节：**
1. 部门管理员登录系统
2. 查看待处理的新员工列表
3. 根据工作需要分配：
   - 应用访问权限
   - 数据查看范围
   - 特殊功能权限
4. 保存权限配置

---

### 步骤6：发送激活邮件

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S6 |
| 步骤名称 | 发送激活邮件 |
| 执行角色 | 系统（自动） |
| 输入 | 用户创建完成、权限分配完成 |
| 输出 | 账号激活邮件 |

**邮件内容：**
- 欢迎词
- 系统访问地址
- 用户名（工号）
- 初始密码
- 激活链接（有效期7天）
- 首次登录指引

---

### 步骤7：激活账号

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S7 |
| 步骤名称 | 激活账号 |
| 执行角色 | 新员工 |
| 输入 | 激活邮件 |
| 输出 | 账号激活状态 |

**操作细节：**
1. 新员工收到激活邮件
2. 点击激活链接
3. 验证链接有效性
4. 账号状态变更为"已激活"

---

### 步骤8：首次登录

| 属性 | 描述 |
|-----|------|
| 步骤编号 | S8 |
| 步骤名称 | 首次登录 |
| 执行角色 | 新员工 |
| 输入 | 用户名、初始密码 |
| 输出 | 登录成功、强制改密 |

**操作细节：**
1. 访问System平台登录页
2. 输入用户名（工号）和初始密码
3. 系统检测到首次登录
4. 强制要求修改密码
5. 修改成功后进入工作台

**业务规则：**
- 首次登录必须修改密码
- 新密码必须符合密码策略
- 修改成功后初始密码失效

## 四、异常流程

### 4.1 入职通知信息不完整

| 场景 | 处理方案 |
|-----|---------|
| 缺少部门信息 | 联系HR专员补充 |
| 缺少岗位信息 | 使用默认角色，后续调整 |
| 工号重复 | 联系HR专员确认 |

### 4.2 用户创建失败

| 场景 | 处理方案 |
|-----|---------|
| 用户名已存在 | 检查是否为重复入职，或联系HR确认工号 |
| 邮箱格式错误 | 联系HR专员修正邮箱 |
| 系统异常 | 记录错误日志，联系技术支持 |

### 4.3 激活链接过期

| 场景 | 处理方案 |
|-----|---------|
| 超过7天未激活 | 系统管理员重新发送激活邮件 |
| 链接被误删 | 联系系统管理员重新发送 |

## 五、业务规则汇总

| 规则编号 | 规则描述 | 适用步骤 |
|---------|---------|---------|
| BR-001 | 用户名必须使用工号 | S2 |
| BR-002 | 初始密码有效期7天 | S2, S6 |
| BR-003 | 首次登录必须修改密码 | S8 |
| BR-004 | 密码必须符合复杂度要求 | S8 |
| BR-005 | 部门权限由部门管理员分配 | S5 |
| BR-006 | 角色分配基于岗位自动匹配 | S3 |

## 六、流程指标

| 指标 | 目标值 | 说明 |
|-----|-------|------|
| 流程完成时间 | ≤ 30分钟 | 从通知到账号可用 |
| 用户创建时间 | ≤ 5分钟 | 系统管理员操作时间 |
| 权限分配时间 | ≤ 10分钟 | 部门管理员操作时间 |
| 激活率 | ≥ 95% | 7天内激活比例 |
| 首次登录成功率 | ≥ 98% | 首次登录成功比例 |
