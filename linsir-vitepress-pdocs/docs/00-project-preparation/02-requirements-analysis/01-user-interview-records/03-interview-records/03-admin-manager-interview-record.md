## 二、访谈内容

### 2.1 用户管理场景

**问：请描述一下您目前的日常工作流程？**

**答：**
我的日常工作主要包括：

**用户管理方面：**
- 每天处理3-5个新员工入职账号申请
- 每周处理10+个权限变更申请
- 每月处理5-8个离职员工账号清理
- 处理各种密码重置请求（平均每天5-10个）

**组织架构方面：**
- 维护公司组织架构信息
- 处理部门变更、人员调动
- 更新部门负责人信息

**系统支持方面：**
- 解答员工系统使用问题
- 协调处理系统故障
- 收集用户反馈和需求

**关键发现：**
- 入职、离职、权限变更是高频操作
- 密码重置请求量大
- 需要处理各种日常运维问题

---

**问：新员工入职时，账号开通的流程是怎样的？**

**答：**
目前的入职账号开通流程：

**流程步骤：**
1. HR在HR系统提交入职申请
2. 我收到邮件通知
3. 在OA系统创建账号
4. 在财务系统创建账号（如需要）
5. 在HR系统创建账号
6. 手动发送账号信息给新员工

**耗时：**
- 单个账号开通：30-60分钟
- 批量入职（10人）：需要一整天

**痛点：**
- 需要在多个系统重复操作
- 账号信息需要手动同步
- 容易遗漏某些系统
- 新员工第一天往往无法使用系统

**关键发现：**
- 多系统重复操作
- 耗时长（30-60分钟/人）
- 容易遗漏

---

**问：员工离职时，账号处理的流程是怎样的？**

**答：**
离职账号处理流程：

**当前流程：**
1. HR提交离职申请
2. 我收到离职通知
3. 手动禁用各系统账号：
   - OA系统
   - 财务系统
   - HR系统
   - 其他业务系统
4. 记录离职时间和操作

**问题：**
- 容易遗漏某些系统的账号
- 离职后账号可能还在某些系统中活跃
- 数据归属问题（离职员工创建的数据）
- 没有统一的离职检查清单

**风险：**
- 前员工可能还能访问系统
- 数据安全风险
- 合规审计问题

**关键发现：**
- 手动操作容易遗漏
- 存在安全风险
- 缺乏统一检查清单

---

**问：员工转岗时，权限变更的流程是怎样的？**

**答：**
转岗权限变更流程：

**当前流程：**
1. 部门主管提交转岗申请
2. 我收到转岗通知
3. 手动调整各系统权限：
   - 禁用原部门权限
   - 开通新部门权限
   - 调整数据访问范围
4. 通知员工权限已变更

**耗时：**
- 单个转岗：20-40分钟
- 涉及系统越多，时间越长

**问题：**
- 权限调整容易出错
- 新旧权限交接不清
- 历史权限遗留
- 员工需要重新熟悉新系统

**关键发现：**
- 权限调整耗时长
- 容易出错
- 历史权限清理困难

### 2.2 组织架构管理

**问：组织架构管理的现状和痛点是什么？**

**答：**
组织架构管理现状：

**现状：**
- 组织架构在HR系统维护
- 每月手动同步到OA系统
- 其他系统各自维护

**痛点：**
1. **数据不一致** - 各系统部门名称、层级不一致
2. **同步延迟** - 组织架构变更后，需要1-2天才能同步到所有系统
3. **历史数据** - 部门合并/拆分时，历史数据处理困难
4. **虚拟团队** - 项目组、临时团队的组织架构无法体现

**具体案例：**
- 上个月技术部拆分为前端部和后端部，花了3天时间才在所有系统中调整完毕
- 有员工在OA系统中属于"技术部"，在HR系统中属于"研发中心"

**关键发现：**
- 数据不一致问题严重
- 同步延迟1-2天
- 部门变更处理困难

---

**问：部门合并或拆分时，系统如何处理？**

**答：**
部门变更处理：

**合并场景：**
- 需要确定合并后的部门名称
- 需要处理原部门的用户归属
- 需要调整权限和数据归属
- 需要通知所有相关人员

**拆分场景：**
- 需要确定新部门的层级关系
- 需要分配人员到新部门
- 需要重新分配权限
- 需要处理历史数据

**当前做法：**
- 手动在各系统中调整
- 制作Excel表格记录变更
- 逐个通知系统管理员

**期望：**
- 一键完成部门变更
- 自动处理用户归属
- 自动调整权限
- 保留历史数据

**关键发现：**
- 手动处理效率低
- 期望自动化处理
- 需要保留历史数据

---

**问：岗位管理的现状如何？**

**答：**
岗位管理现状：

**现状：**
- 岗位信息在HR系统维护
- 其他系统没有岗位概念，只有角色
- 岗位和权限没有关联

**问题：**
- 岗位信息无法同步到其他系统
- 岗位变动时权限需要手动调整
- 无法按岗位统计和分析

**期望：**
- 统一的岗位管理
- 岗位与权限自动关联
- 支持岗位变更自动调整权限

**关键发现：**
- 岗位管理分散
- 岗位与权限未关联
- 期望岗位权限联动

**期望：**
- 统一的权限申请入口

**关键发现：**
- 申请方式混乱

## 三、关键发现总结

### 3.1 核心痛点
1. **多系统操作** - 入职、离职需要在多个系统重复操作
2. **手工管理** - Excel管理权限，效率低易出错
3. **密码重置** - 每月120-200次，耗时20-40小时

### 3.2 效率目标
1. **入职开通** - 从2小时缩短到10分钟
2. **权限变更** - 从1天缩短到1小时
3. **密码重置** - 从人工到自助

### 3.3 功能需求
1. **批量操作** - 支持批量入职、批量权限变更
2. **自助服务** - 密码重置、权限申请自助化
