## 一、识别方法

### 1.1 识别来源

| 来源 | 说明 | 已识别干系人 |
|-----|------|-------------|
| **用户访谈** | 已完成的7场访谈 | CEO、IT总监、行政经理、业务系统负责人、运维主管、HR专员、开发工程师 |
| **组织架构** | 公司组织结构 | 各部门负责人、关键岗位 |
| **业务流程** | 业务流程涉及人员 | 流程参与者、审批者 |
| **系统使用** | 系统最终用户 | 所有员工、外部用户 |

### 1.2 识别标准

```
干系人识别标准：
├─ 对项目有决策权或影响力
├─ 受项目结果影响
├─ 参与项目实施
├─ 使用项目产出
└─ 对项目成功有关键作用
```

## 三、干系人分类

### 3.1 按参与程度分类

```
┌─────────────────────────────────────────────────────────────┐
│                      干系人参与程度分类                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  核心干系人          重要干系人          一般干系人          │
│  ├─ CEO              ├─ 各部门经理       ├─ 普通员工        │
│  ├─ IT总监           ├─ 业务系统负责人   ├─ 外部供应商      │
│  ├─ 行政经理         ├─ 运维主管         └─ ...             │
│  └─ 系统管理员       └─ HR专员                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 按影响程度分类

| 影响程度 | 干系人 | 管理策略 |
|---------|-------|---------|
| **高影响** | CEO、IT总监、行政经理、系统管理员 | 重点管理，密切沟通 |
| **中影响** | 各部门经理、业务系统负责人、运维主管 | 定期沟通，保持参与 |
| **低影响** | 普通员工、外部供应商 | 适度沟通，信息同步 |

### 3.3 按支持程度分类

| 支持程度 | 干系人 | 特征 |
|---------|-------|------|
| **积极支持** | CEO、IT总监 | 主动推动项目，提供资源 |
| **支持** | 行政经理、业务系统负责人 | 配合项目实施，提供支持 |
| **中立** | 部分部门经理 | 观望态度，等待效果 |
| **潜在抵触** | 部分老员工 | 担心改变，需要引导 |

## 五、关键干系人识别

### 5.1 项目成功关键干系人

| 序号 | 干系人 | 关键作用 | 必须满足的需求 |
|-----|-------|---------|---------------|
| 1 | CEO | 战略决策、资源支持 | 数据安全、效率提升 |
| 2 | IT总监 | 技术决策、实施把控 | 技术可行性、系统集成 |
| 3 | 行政经理 | 业务需求、日常管理 | 流程简化、权限管理 |
| 4 | 系统管理员 | 系统运维、用户支持 | 易维护性、稳定性 |

### 5.2 潜在风险干系人

| 干系人 | 潜在风险 | 应对策略 |
|-------|---------|---------|
| 部分老员工 | 抵触新系统 | 加强培训，展示价值 |
| 外部供应商 | 配合度不确定 | 明确合同，建立沟通机制 |
