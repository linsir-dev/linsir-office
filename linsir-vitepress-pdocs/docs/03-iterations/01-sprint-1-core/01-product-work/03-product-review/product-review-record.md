## 二、会议议程

### 2.1 需求背景说明（5分钟）

**需求来源：**

基于公司业务发展需要，现有系统管理功能分散，权限控制粒度不足，组织架构管理不完善，缺乏完整的审计日志功能。为了提升系统管理效率，规范权限控制，完善组织架构管理，特启动本次迭代开发。

**业务价值：**

1. **提升管理效率**：统一的用户、角色、菜单管理，减少运维成本
2. **规范权限控制**：细粒度的RBAC权限模型，保障系统安全
3. **完善组织架构**：树形部门结构，支持多层级管理
4. **增强审计能力**：完整的操作日志和访问日志，满足合规要求
5. **数据可视化**：工作台数据展示，提供决策支持

**用户场景：**

- **系统管理员**：需要管理用户、角色、菜单，配置系统权限
- **部门负责人**：需要管理部门、职位、员工信息
- **运维人员**：需要查看系统日志，监控系统运行状态
- **普通用户**：需要查看工作台数据，了解系统使用情况

### 2.3 技术可行性讨论（15分钟）

**技术方案评估：**

| 模块 | 技术方案 | 可行性 | 风险 |
|------|----------|--------|------|
| 认证模块 | JWT + Redis + Spring Security | ✅ 可行 | Token刷新机制需优化 |
| 用户管理 | 标准CRUD + 分页查询 | ✅ 可行 | 无 |
| 角色管理 | RBAC模型 + 权限树 | ✅ 可行 | 权限缓存策略需设计 |
| 菜单管理 | 树形结构 + 递归查询 | ✅ 可行 | 大数据量时性能需优化 |
| 部门管理 | 树形结构 + 路径枚举 | ✅ 可行 | 层级深度建议限制5层 |
| 职位管理 | 标准CRUD + 部门关联 | ✅ 可行 | 无 |
| 职称管理 | 标准CRUD + 级别枚举 | ✅ 可行 | 无 |
| 员工管理 | 标准CRUD + 多表关联 | ✅ 可行 | 关联查询性能需优化 |
| 审计日志 | AOP拦截 + 异步写入 | ✅ 可行 | 日志量大数据存储需规划 |

5. **响应式**：支持 1366px 及以上分辨率

## 四、会议纪要

**主要讨论内容：**

1. **认证模块设计讨论**
   - 确认采用JWT + Redis方案，支持Token自动刷新
   - 第三方登录（微信、钉钉）作为后续迭代功能
   - 账号锁定功能作为增强需求纳入迭代

2. **工作台数据展示讨论**
   - 确认展示6个核心统计指标
   - 增加快捷入口功能，提升用户体验
   - 图表采用ECharts，支持响应式

3. **组织架构设计讨论**
   - 确认树形部门结构，支持拖拽排序
   - 员工关联部门和职位，支持批量调整
   - 数据权限后续迭代支持

4. **审计日志设计讨论**
   - 确认操作日志和访问日志分开存储
   - 增加日志级别筛选功能
   - 日志归档策略后续讨论

5. **性能优化讨论**
   - 树形数据查询采用路径枚举优化
   - 权限数据使用Redis缓存
   - 日志写入采用异步方式

**关键决策：**

1. **采用RBAC权限模型**，支持按钮级权限控制
2. **部门层级限制5层**，避免过深影响性能
3. **日志异步写入**，避免影响主业务流程
4. **支持多UI框架**，Element Plus为主，其他框架后续适配
5. **迭代周期2周**，3月27日正式启动开发

**遗留问题：**

1. 日志归档策略需要运维团队进一步评估
2. 第三方登录的OAuth配置需要申请开发者账号
3. 数据权限的细粒度控制需要业务方确认规则
4. 性能测试基准需要在开发完成后确定
