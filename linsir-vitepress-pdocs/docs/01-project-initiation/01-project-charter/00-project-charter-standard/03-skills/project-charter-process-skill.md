# Skill: 项目章程制定流程

## 描述

指导项目章程制定全过程，包括项目基本信息定义、目标定义、范围界定、干系人识别、约束与假设识别、风险识别、里程碑定义、资源需求估算和章程审批。

## 调用方式

当用户需要制定项目章程、编写项目章程文档或进行项目正式授权时，调用此skill。

## 执行流程

### 步骤1：项目基本信息定义

**任务**：明确项目的基本标识和授权信息

**操作指南**：
1. 确定项目名称和编号（格式：SYS-PI-XXX）
2. 指定项目发起人（通常为业务副总裁或总监级别）
3. 指定项目经理（明确姓名和职位）
4. 记录项目创建日期
5. 定义项目经理授权范围：
   - 预算审批权限
   - 人员调配权限
   - 技术决策权限
   - 供应商选择权限
6. 明确决策权限边界

**输出文档**：
- `01-charter-documents/01-project-identity.md` - 项目标识信息
- `01-charter-documents/02-project-authorization.md` - 项目授权书

**审核要求**：项目经理审核基本信息的准确性

---

### 步骤2：项目目标定义

**任务**：明确项目的业务目标和成功标准

**操作指南**：
1. 定义3-5个可衡量的业务目标：
   - 使用SMART原则（具体、可衡量、可达成、相关、有时限）
   - 每个目标都要有量化指标
2. 对目标进行优先级排序（P0-P2）
3. 制定项目成功的衡量指标：
   - 业务指标（如效率提升百分比）
   - 技术指标（如系统性能指标）
   - 质量指标（如缺陷率）
4. 定义验收标准：
   - 功能验收标准
   - 性能验收标准
   - 安全验收标准

**输出文档**：
- `01-charter-documents/03-business-objectives.md` - 业务目标
- `01-charter-documents/04-success-criteria.md` - 成功标准

**审核要求**：业务负责人审核目标的合理性和可达成性

---

### 步骤3：项目范围界定

**任务**：明确项目的边界和主要交付物

**操作指南**：
1. 编写项目范围描述：
   - 项目背景
   - 项目目的
   - 预期成果
2. 列出主要交付物清单：
   - 软件系统
   - 文档资料
   - 培训材料
   - 其他交付物
3. 明确包含范围（In Scope）：
   - 功能模块
   - 用户群体
   - 集成系统
4. 明确不包含范围（Out of Scope）：
   - 明确排除的功能
   - 不包含的集成
   - 后期规划内容

**输出文档**：
- `01-charter-documents/05-project-scope.md` - 项目范围说明
- `01-charter-documents/06-scope-boundaries.md` - 范围边界

**审核要求**：项目团队评审范围的完整性

---

### 步骤4：干系人识别

**任务**：识别项目关键干系人

**操作指南**：
1. 识别所有干系人：
   - 内部干系人（管理层、业务部门、技术团队）
   - 外部干系人（客户、供应商、监管机构）
2. 分析影响力和利益：
   - 使用权力/利益矩阵
   - 评估影响程度（高/中/低）
   - 评估利益相关度（高/中/低）
3. 制定沟通策略概要：
   - 沟通频率
   - 沟通方式
   - 信息内容
4. 记录干系人信息：
   - 姓名、职位、部门
   - 角色和职责
   - 期望和关注点

**输出文档**：
- `01-charter-documents/07-stakeholder-register.md` - 干系人登记册

**审核要求**：项目经理审核干系人识别的完整性

---

### 步骤5：项目约束与假设识别

**任务**：识别项目的限制条件和假设条件

**操作指南**：
1. 识别时间约束：
   - 项目截止日期
   - 关键里程碑时间
   - 业务季节性要求
2. 识别预算约束：
   - 预算上限
   - 资金来源
   - 成本控制要求
3. 识别资源约束：
   - 可用人力资源
   - 硬件资源限制
   - 软件许可限制
4. 识别技术约束：
   - 技术选型限制
   - 系统集成要求
   - 安全合规要求
5. 记录项目假设条件：
   - 业务假设
   - 技术假设
   - 资源假设
6. 制定假设验证计划：
   - 验证方法
   - 验证时间
   - 责任人

**输出文档**：
- `01-charter-documents/08-project-constraints.md` - 约束条件
- `01-charter-documents/09-assumption-log.md` - 假设日志

**审核要求**：各职能负责人审核相关约束的准确性

---

### 步骤6：项目风险初步识别

**任务**：识别项目高层级风险

**操作指南**：
1. 识别Top 5-10高层风险：
   - 技术风险
   - 业务风险
   - 资源风险
   - 进度风险
   - 外部风险
2. 评估风险影响：
   - 影响程度（高/中/低）
   - 发生概率（高/中/低）
   - 风险等级（严重/中等/轻微）
3. 制定初步应对策略：
   - 规避策略
   - 转移策略
   - 减轻策略
   - 接受策略
4. 记录风险信息：
   - 风险描述
   - 风险类别
   - 应对措施
   - 责任人

**输出文档**：
- `01-charter-documents/10-risk-register.md` - 风险登记册（初版）

**审核要求**：项目团队评审风险识别的全面性

---

### 步骤7：项目里程碑定义

**任务**：确定项目关键里程碑

**操作指南**：
1. 识别5-8个关键里程碑：
   - 项目启动
   - 需求完成
   - 设计完成
   - 开发完成
   - 测试完成
   - 上线发布
   - 项目收尾
2. 估算里程碑时间：
   - 计划日期
   - 缓冲时间
   - 依赖关系
3. 定义里程碑交付物：
   - 主要交付物
   - 验收标准
   - 验收人
4. 制定里程碑计划：
   - 里程碑清单
   - 时间安排
   - 责任人

**输出文档**：
- `01-charter-documents/11-milestone-schedule.md` - 里程碑计划

**审核要求**：项目经理审核里程碑的合理性

---

### 步骤8：项目资源需求估算

**任务**：估算项目所需资源

**操作指南**：
1. 估算人力资源需求：
   - 角色定义
   - 人数需求
   - 技能要求
   - 时间投入
2. 估算硬件资源需求：
   - 服务器需求
   - 网络设备
   - 开发设备
   - 测试设备
3. 估算软件资源需求：
   - 开发工具
   - 测试工具
   - 软件许可
   - 云服务
4. 估算外部资源需求：
   - 外包服务
   - 咨询服务
   - 培训服务
5. 汇总资源需求：
   - 资源清单
   - 成本估算
   - 获取计划

**输出文档**：
- `01-charter-documents/12-resource-requirements.md` - 资源需求估算

**审核要求**：
- 技术负责人审核技术资源需求
- 财务负责人审核预算合理性

---

### 步骤9：项目章程汇总与审批

**任务**：完成项目章程的审批流程

**操作指南**：
1. 整合所有章程内容：
   - 汇总各文档核心内容
   - 确保逻辑一致性
   - 检查完整性
2. 进行内部评审：
   - 项目团队评审
   - 收集反馈意见
   - 修改完善
3. 提交发起人审批：
   - 准备审批材料
   - 安排审批会议
   - 记录审批意见
4. 获得管理层签字：
   - 技术负责人签字
   - 业务负责人签字
   - 财务负责人签字
   - 法务负责人签字
5. 正式发布章程：
   - 分发章程文档
   - 召开启动会议
   - 存档备案

**输出文档**：
- `01-charter-documents/00-project-charter.md` - 项目章程汇总
- `01-charter-documents/13-charter-approval.md` - 章程审批
- `01-charter-documents/00-project-charter-review.md` - 审核记录

**审核要求**：
- 团队评审：内容完整性
- 技术审核：技术可行性
- 业务审核：需求确认
- 财务审核：预算合理性
- 法务审核：合规性
- 发起人批准：正式授权

## 质量标准

### 文档质量标准
- 所有文档必须包含标准头部信息（文档编号、版本、日期、状态）
- 文档内容必须完整，无重大遗漏
- 文档之间逻辑一致，无矛盾
- 所有数据必须有来源或依据

### 流程质量标准
- 所有步骤必须按顺序执行
- 每个步骤必须通过审核才能进入下一步
- 所有审核意见必须记录并处理
- 所有签字必须完整

## 常见问题

**Q1：项目章程和项目计划有什么区别？**
A：项目章程是高层级的授权文档，定义项目的基本框架和边界；项目计划是详细的执行文档，定义具体的任务、时间和资源安排。

**Q2：项目章程需要多详细？**
A：项目章程应该足够详细以提供清晰的指导和授权，但不需要包含执行层面的细节。通常10-20页为宜。

**Q3：谁应该参与章程制定？**
A：项目经理负责编制，项目发起人提供输入，核心团队成员参与评审，各职能负责人参与审核。

**Q4：章程批准后还能修改吗？**
A：章程批准后，重大变更需要经过正式的变更控制流程，由项目发起人批准。
